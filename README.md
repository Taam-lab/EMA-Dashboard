# 20일 신고가 눌림목 · ETF (IRP)

국내 상장 ETF 로만 매매하는 페이퍼 포트폴리오 대시보드. IRP(퇴직연금) 계좌 규칙에 맞춰,
레버리지·인버스·파생형 ETF 는 사지 않고 위험자산을 70% 까지만 담는다.

진입·청산·국면 규칙은 코스피 주식 버전(태그 `stock-v1`, 2026-09-10 ~ 10-22 기록 포함)과 같다.
바뀐 것은 매매 대상(ETF)과 계좌 제약(IRP)뿐이다. **이 조합은 백테스트된 적이 없다** — 주식 버전
백테스트 성과(+235%)를 기대치로 삼으면 안 된다.

## 구성

| 파일 | 역할 |
|---|---|
| `config.py` | 전략 파라미터 + 계좌·유니버스 설정 |
| `strategy.py` | 순수 전략 로직 (지표·진입·청산·방어 판정) — 테스트 대상 |
| `data.py` | 시세 수집 + 로컬 parquet 캐시 (KRX 일괄 시세, ETF 유니버스 선정) |
| `engine.py` | 페이퍼 포트폴리오 상태 머신 (정수 주식수 원장, 위험자산 한도) |
| `run_daily.py` | 데일리 배치 (`--preview` 기록 없이 주문만, `--monitor` 장중 현황만) |
| `dashboard.py` | Streamlit 2탭 대시보드 |
| `test_strategy.py` | 회귀 테스트 |
| `daily.ps1` | 작업 스케줄러 러너 — 평일 08:00 · 11:30 · 15:05 KST (주 경로) |
| `.github/workflows/daily.yml` | 평일 16:30 KST 안전망 — 로컬이 그날을 처리하지 못했을 때만 실행 |

## 설치 · 실행

```bash
pip install -r requirements-daily.txt
```

KRX 가 로그인 필수라 계정을 환경변수로 넣어야 합니다 (PowerShell):

```powershell
$env:KRX_ID="<KRX 아이디>"; $env:KRX_PW="<KRX 비밀번호>"
```

```bash
python run_daily.py --preview    # 기록하지 않고 오늘 낼 주문만 (15:00 이후)
python run_daily.py --monitor    # 장중 현황만, 원장 안 건드림 (09:00~15:30)
python run_daily.py              # 갱신 + 체결 기록 (08:00 개장 전, 또는 15:00 이후)
streamlit run dashboard.py
```

첫 실행은 ETF 이력 캐시가 없어서 KRX 일괄 시세를 하루씩 받아 약 300거래일치를 만듭니다(약 3~5분, 1회).

## 운용 흐름

| 시각 | 하는 일 | 원장 |
|---|---|---|
| **08:00** | 전 거래일 확정 종가로 평가 갱신, 유니버스 밖 ETF 캐시도 갱신 | 매매 없음 |
| **11:30** | 장중 시세로 손익·손절선 거리 확인 | 건드리지 않음 |
| **15:05** | 그 시점 스냅샷으로 신호 판정 + 체결 기록 → **마감 동시호가(15:20~15:30)에 주문** | 체결 기록 |

증권사에 **스탑주문은 걸지 마세요.** 엔진은 15:05 스냅샷으로만 청산을 판정합니다. 장중에 손절선을 찔렀다
회복하면 청산으로 잡지 않으므로, 스탑주문을 걸면 기록과 실거래가 갈립니다.

## 규칙

### 유니버스 — 시총 상위 200

국내 상장 ETF 1,183개 중 아래를 거른 뒤 시가총액(상장좌수 × 종가) 상위 200개.
분류는 전부 KRX 공식 기본정보 기준입니다(이름 추측 아님).

| 제외 | 이유 |
|---|---|
| 추적배수가 '일반'이 아닌 것 (2X 레버리지·1X/2X 인버스) | IRP 매수 불가 |
| 복제방법 '합성' | 파생형 — IRP 매수 불가 |
| 이름·기초지수에 '선물' | KRX 는 '실물'로 분류해도 실제론 선물 100% 인 파생형 (`KODEX 미국S&P500선물(H)` 등) |
| 주식형이 아닌 것 (채권·머니마켓·원자재 등) | 머니마켓·CD금리 ETF 는 이자가 매일 붙어 거의 매일 20일 신고가를 찍고, 손절·데드크로스가 안 걸려 슬롯을 영구 점유한다. 채권·원자재는 변동성이 달라 −7% 손절 같은 파라미터가 안 맞는다 |
| 같은 기초지수의 두 번째 이하 | 코스피200 추종만 10개, S&P500 9개다. 그대로 두면 한 지수가 강한 날 슬롯 여러 개가 같은 지수로 차서 분산이 사라진다. TR/PR·원화환산 표기 차이도 같은 지수로 묶고 시총 1위만 남긴다. 환헤지(H)는 기초지수가 달라 별개로 남는다 |

→ 매수 가능 734개 (국내 409 · 해외 304 · 혼합 21) → 지수 중복 제거 575개 → 상위 200 (10/22 기준 국내 116 · 해외 79 · 혼합 5).

증권사에서 IRP 매수가 막힌 ETF 가 신호로 뜨면 `config.ETF_EXCLUDE_TICKERS` 에 넣으세요. 특히 커버드콜 ETF 는
'실물'이라 남겨뒀지만 증권사마다 IRP 허용 여부가 다를 수 있습니다.

### 진입 — 세 조건 모두
전일 20일 신고가 · 당일 −5% ~ 0% 눌림 · 120일 수익률 상위 50%. 신호가 슬롯보다 많으면 모멘텀 높은 순.
과열(코스피 이격도 ≥120)이면 신규매수 중단. **같은 기초지수를 이미 보유 중이면 사지 않음.**

### 청산 — 셋 중 먼저
`체결선 = max(진입가 × 0.93, 고점종가 × 0.90)` 이하 (갭하락이면 시가) · EMA 5/20 데드크로스.

### 사이징 — 위험자산 70%
최대 10종목 × 자본의 **7%** = 70%. 주식 버전(10% × 10)에서 슬롯 수 대신 비중을 줄여 분산 폭을 유지했습니다.
매수할 때마다 **위험자산 한도를 확인**해 남은 한도까지만 삽니다. 보유분이 올라 70% 를 넘는 것은 허용되지만
그 상태에선 빈 슬롯이 있어도 신규 매수를 하지 않습니다(퇴직연금 규정과 같은 방식). 나머지 30%+ 는 현금.

### 방어 — 인버스 대신 현금
IRP 는 인버스 매수가 금지라 원래의 인버스 헷지는 못 합니다. 같은 규칙(코스피 이격도 ≤99 켜짐, ≥101 해제)으로
방어 비중 10/20/30% 를 정하고 그만큼 **롱 슬롯을 9/8/7개로 줄여 현금으로** 둡니다. 하락장에서 노출을 줄이는
부분은 남지만, 인버스로 하락을 상쇄하던 부분은 사라집니다. 일반 계좌라면 `config.HEDGE_ENABLED = True`.

### 비용
수수료 편도 0.015%. ETF 는 증권거래세 면제, 매매차익은 연금계좌라 과세이연 — 매매 시점 세금 없음.

## ⚠️ 알아둘 점

1. **페이퍼(모의)입니다.** 주문은 하지 않습니다. 대시보드를 보고 계좌에서 직접 체결하세요.
2. **검증되지 않은 조합입니다.** 파라미터는 코스피 개별주식으로 검증됐습니다. ETF 는 변동성이 낮아 −5% 눌림·−7% 손절이 훨씬 드물게 걸리고, 신호 빈도도 다릅니다. 라이브 기록이 첫 검증입니다.
3. **국면 판단은 코스피 기준입니다.** 해외지수 ETF 를 넣었지만 과열·방어 판단은 코스피 이격도로만 합니다. 미국 지수가 무너지는데 코스피는 멀쩡하면 방어가 켜지지 않습니다.
4. **분배금은 반영하지 않습니다.** 가격은 KRX 원주가(분배금 미조정)를 씁니다. 주식 버전이 현금배당을 조정하지 않은 것과 같은 처리입니다. 그래서 분배금이 큰 ETF(월배당·커버드콜)는 가격이 그만큼 내려가 모멘텀이 낮게 잡히고, 보유 중 받는 분배금도 원장에 현금으로 들어오지 않습니다.
   네이버 수정주가는 분배금을 조정해서(위클리 커버드콜 최대 7.4%) KRX 시세와 섞으면 경계에서 가짜 상승이 생기므로 ETF 에는 쓰지 않습니다.
5. **분할·병합은 하루 ±30.5% 초과 변동으로 감지해 과거 가격을 조정합니다.** ETF 일괄 시세엔 등락률이 없어 주식 버전처럼 기준가로 판정하지 못합니다. 1배수 주식형 ETF 가 실제로 하루 30% 넘게 움직이는 일은 사실상 없습니다.
6. **엔진은 분할 때 진입가를 조정하지 않습니다.** 보유 ETF 가 분할되면 가짜 손절이 나옵니다. 그런 날은 주문 목록과 대시보드에 경고가 뜹니다.
7. **15:05 스냅샷 체결이라 종가 체결 백테스트와 차이가 있습니다.**

## 데이터 수집

매 실행은 KRX ETF 일괄 시세(하루치 전종목, 1회 약 1초)로 캐시의 최근 5거래일을 덮어씁니다.
ETF 종목명·분류는 KRX ETF 기본정보 표 하나로 받습니다(0.4초) — pykrx 의 `get_etf_ticker_name` 은
ETN·ELW 까지 합쳐 받느라 1건에 6초(1,183개면 2시간)입니다. 종목별 이력 조회(`get_etf_ohlcv_by_date`)도
건당 7~12초라, 처음 이력은 일괄 시세를 하루씩 받아 만듭니다.

KRX 로그인은 pykrx 를 import 하는 순간 일어나서, 로그인이 실패하면(일시 차단·점검) 예전엔 재시도 없이 바로
죽었습니다. 지금은 15·30·45초 간격으로 다시 시도합니다.
