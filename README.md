# 20일 신고가 눌림목 전략 — 데일리 대시보드

거래소(KRX) 데이터로 매일 자동 갱신되는 페이퍼 포트폴리오 대시보드.
전략은 백테스트 확정판(20일 신고가 눌림목 + 단계별 인버스 헷지)을 그대로 구현.

## 구성

| 파일 | 역할 |
|---|---|
| `config.py` | 전략 파라미터 (확정값) |
| `strategy.py` | 순수 전략 로직 (지표·진입·청산·헷지 판정) — 테스트 대상 |
| `data.py` | 시세 수집 + 로컬 parquet 캐시 (KRX 일괄 시세 주 경로, 권리 변동 자동 조정) |
| `engine.py` | 페이퍼 포트폴리오 상태 머신 (정수 주식수 원장) |
| `run_daily.py` | 데일리 배치: 데이터 갱신 → 엔진 진행 → snapshot 저장 (`--preview` 로 기록 없이 주문만 확인) |
| `dashboard.py` | Streamlit 2탭 대시보드 |
| `test_strategy.py` | pytest 회귀 테스트 |
| `daily.ps1` | 작업 스케줄러 러너 — 평일 08:00 · 11:30 · 15:05 KST (주 경로) |
| `.github/workflows/daily.yml` | 평일 16:30 KST 안전망 — PC 가 꺼졌던 날만 기록을 메움 (GitHub Actions) |

## 설치

```bash
pip install -r requirements-daily.txt
```

`requirements.txt` 는 대시보드 구동에만 필요한 것(streamlit·pandas·numpy)이고,
`requirements-daily.txt` 는 여기에 데이터 수집용 pykrx·pyarrow 를 더한 것입니다.
Streamlit Cloud 는 `requirements.txt` 만 읽으므로 배포가 가볍고 빠릅니다.

## 실행

KRX 가 로그인 필수라, 먼저 계정을 환경변수로 넣어야 합니다 (PowerShell):

```powershell
$env:KRX_ID="<KRX 아이디>"; $env:KRX_PW="<KRX 비밀번호>"
```

```bash
# 0) 기록하지 않고 오늘 낼 주문만 미리보기
python run_daily.py --preview

# 0-1) 장중 현황만 보기 (원장 안 건드림, 09:00~15:30 에 실행 가능)
python run_daily.py --monitor

# 1) 데이터 수집 + 포트폴리오 갱신 (첫 실행은 수백 종목이라 느립니다)
#    15:00 KST 이전에는 실행이 거부됩니다 — 종가 대용으로 쓰기엔 이른 가격이라서.
python run_daily.py

# 2) 대시보드 실행
streamlit run dashboard.py
```

`run_daily.py` 는 `portfolio_state.json`(누적 상태)과 `snapshot.json`(대시보드용 현황)을 만듭니다.
대시보드는 이 두 파일만 읽으므로 pykrx 없이도 뜹니다.

## 자동 데일리 업데이트

기본은 **이 PC 의 작업 스케줄러**입니다 (`daily.ps1`, 평일 **08:00 · 11:30 · 15:05 KST**).

| 시각 | 하는 일 | 원장 |
|---|---|---|
| **08:00** | 개장 전 평가 갱신. 전 거래일 확정 종가로 평가손익·손절선 근접을 다시 계산 | 매매 없음(전 거래일은 이미 처리됨) |
| **11:30** | 장중 모니터링(`--monitor`). 지금 시세로 손익과 손절선까지 거리를 확인 | **건드리지 않음** — `snapshot.json` 만 갱신 |
| **15:05** | 주문 구간. 그 시점 스냅샷으로 신호를 판정하고 체결까지 기록. 이걸 보고 마감 동시호가에 주문 | 체결 기록 |

11:30 실행은 일부러 매매를 기록하지 않습니다. 장중 가격으로 체결을 남기면 마감까지 가격이 움직여도 되돌릴 수 없습니다(9/10 에 13:47 실행이 장중가로 6종목을 잡아 원장을 리셋해야 했습니다). 그래서 `--monitor` 는 `portfolio_state.json` 을 열지 않고, 화면에도 "매매는 기록되지 않았습니다" 배너가 뜹니다.

GitHub Actions(`.github/workflows/daily.yml`)도 남아 있지만 **예약 실행이 best-effort 라 정시성이 없습니다** — 실제로 9/10 은 5시간 지연, 9/11 은 미실행이었습니다. 마감 25분 전이라는 타이밍이 곧 기능이라 주 경로를 로컬로 옮겼습니다.
설정은 [DEPLOY.md](DEPLOY.md) 참고.

내 PC 에서 돌리려면 크론(평일 15:05 KST):

```cron
5 15 * * 1-5  cd /path/to/quant_dashboard && /usr/bin/python run_daily.py >> run.log 2>&1
```

## 화면

- **메인 탭**: 포트폴리오 수익률(누적 곡선·MDD) / 현재 포지션(진입가 대비 수익률·손절선·위험표시) / 금일 진입 예정 종목 / 금일 청산 예정(위험) 종목
- **매매이력 탭**: 전체 체결 로그 + 승률·손익비·거래당 평균

## 전략 규칙 (요약)

- **유니버스**: 시총 상위 200. 보유 종목이 200위 밖으로 밀려도 청산은 규칙대로, **신규 진입만** 유니버스 제한.
- **진입**(마감 직전 스냅샷): 전일 20일 신고가 + 당일 −5%~0% 눌림 + 120일 모멘텀 상위 50%. 과열(코스피 이격도 EMA50 ≥120) 시 신규매수 금지.
- **청산**(셋 중 먼저): EMA 5/20 데드크로스 / 진입가 −7% / 고점 −10% 트레일. 손절·트레일은 `max(진입가×0.93, 고점×0.90)` 체결, **갭하락 시 시가 체결**.
- **사이징**: 최대 10종목 × 자본 10%, 신호 초과 시 모멘텀 우선.
- **헷지**: 코스피 이격도(EMA50) 단계별 KODEX 인버스 — 96~100→10%, 93~96→20%, <93→30% (켜짐 ≤99, 끔 ≥101). 헷지 비중만큼 롱 슬롯 축소.

## ⚠️ 반드시 알아둘 점

1. **페이퍼(모의)입니다.** 실제 주문은 하지 않습니다. 대시보드의 진입/청산 신호를 보고 증권사에서 직접 체결하세요. 자동매매로 확장하려면 Kiwoom REST 주문 API를 `engine._buy/_sell` 대신 연결해야 합니다.
2. **마감 직전 스냅샷 체결 — 스탑주문을 걸지 마세요.**

   진입 조건이 "당일 등락률 −5%~0%" 라 신호가 종가에 의존합니다. 그런데 **종가를 안 뒤에는 그 가격에 살 수 없습니다.** 그래서 배치를 마감 직전(15:05 KST)에 돌려 **그 시점 스냅샷을 종가 대용으로 판정하고, 그 가격에 체결한 것으로 기록**합니다. 판정 시점과 주문 시점이 같아 룩어헤드가 없습니다.

   운용 흐름: **08:00 어제 결과 확인 → 15:05 배치 → 대시보드 확인 → 마감 동시호가(15:20~15:30)에 주문.**

   아침 실행은 평가만 갱신합니다. 전 거래일은 이미 처리됐으므로 매매를 다시 하지 않습니다 — 아침에 전날 거래를 확정 종가로 재체결해버리면 "그 가격에 살 수 있었는가" 라는 전제가 깨집니다. 다만 그 때문에 **수익률 곡선의 전날 값은 15:05 평가로 남고, 화면의 평가손익은 확정 종가 기준**이라 둘이 미세하게 다릅니다.

   엔진은 이 스냅샷 가격으로만 청산을 판정합니다. 장중에 체결선을 뚫었다가 회복하면 청산으로 잡지 않으므로, 증권사에 스탑주문을 걸어두면 그 자리에서 체결돼버려 기록과 실거래가 갈립니다. 스탑은 걸지 말고 동시호가에 직접 내세요.

   **백테스트와의 차이**: 백테스트는 정확한 종가 체결을 가정했지만 라이브는 15:05 스냅샷입니다. 보통 종가와 근접하지만 동일하지 않으므로, 라이브 성과는 백테스트와 갈릴 수 있습니다(유니버스 롤링과 같은 성격의 예정된 차이).

   장중 실시간 추적으로 바꾸는 것도 가능하지만(증권사 API + 상주 서버 필요), 그러면 장중 꼬리에 걸리는 청산이 늘어 승률·손익비가 달라집니다. **그 버전의 성과는 검증된 적이 없으므로** 바꾸려면 분봉 재백테스트가 선행돼야 합니다. — 2026-09-10 검토 후 현행 유지로 결정.
3. **라이브 유니버스는 롤링.** 백테스트는 2021 시총 고정이었지만, 여기선 매일 상위 200을 다시 뽑습니다. 따라서 라이브 성과는 백테스트와 다를 수 있습니다.
4. **시세 수집과 수정주가.** 매 실행은 KRX 일괄 시세(하루치 전종목을 한 번에)로 캐시의 최근 5거래일을 덮어씁니다. 전체 실행 약 8초(9/14 실측, 이전 방식은 3분).
   분할·병합·유무상증자는 KRX 등락률로 역산한 기준가로 감지하고, 표준 수정주가 계산(기준가 ÷ 전일 종가)으로 과거 가격을 직접 조정합니다. 두 달치 실데이터에서 권리 변동 42건 전부 감지, 정상 5,637건 오탐 0, 네이버 수정주가와 차이 0.02% 이내였습니다. 네이버 수정주가는 캐시가 없는 신규 종목에만 씁니다 — 느리고(200종목 136초), 당일 봉 확정이 늦고, 반영하지 않는 권리 변동도 있었습니다(006740 5:1 분할).
   ⚠️ **엔진은 권리 변동 때 진입가를 조정하지 않습니다.** 보유 종목이 5:1 분할되면 가짜 −80% 손절이 나옵니다. 그런 날은 주문 목록과 대시보드에 경고가 뜨니 주문 전에 직접 확인하세요.
   참고: `strategy.clean_universe`(±30.5% 필터)는 정의만 있고 호출되지 않습니다.
5. **헷지의 알려진 약점.** V자 급락-급반등(예: 2025-04 관세 쇼크)에선 바닥에서 비중을 키웠다 반등에 손실. 추세적 약세장(2022)에선 정상 작동 — 트레이드오프를 인지하고 채택한 설계.
6. **검증 상태.** walk-forward 통과(표본 외 +164~200%, 파라미터 안정). 다만 헷지 임계값은 2022년 약세장 1회 의존 — 라이브 페이퍼로 추가 검증 권장.
